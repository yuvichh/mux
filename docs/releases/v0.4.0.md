**mux 0.4.0 sends a folder with four words, copies from and to any machine
you can `ssh` to, and is up to twenty times as fast with small files.**

```console
$ mux send ./photos
code     polar-bulb-catalog-range
on the other machine, run:  mux get polar-bulb-catalog-range

$ mux get polar-bulb-catalog-range        # on the other machine
./photos	4500007	verified
```

## Install

On macOS or Linux:

```sh
curl -fsSL https://mux.yuvich.com/install.sh | sh
```

It takes the build for your machine, checks it against the
[SHA-256 checksums](https://github.com/yuvichh/mux/releases/download/v0.4.0/checksums-sha256.txt)
of this release and puts `mux` in `~/.local/bin`. Run it again to upgrade.
With Homebrew: `brew install yuvichh/tap/mux`.

| Platform | Executable |
| --- | --- |
| macOS | [Apple silicon](https://github.com/yuvichh/mux/releases/download/v0.4.0/mux-Darwin-arm64) · [Intel](https://github.com/yuvichh/mux/releases/download/v0.4.0/mux-Darwin-x86_64) |
| Linux (glibc 2.17+) | [x86-64](https://github.com/yuvichh/mux/releases/download/v0.4.0/mux-Linux-x86_64) · [ARM64](https://github.com/yuvichh/mux/releases/download/v0.4.0/mux-Linux-aarch64) |
| Windows | [x64 executable](https://github.com/yuvichh/mux/releases/download/v0.4.0/mux.exe) |

On Windows, open PowerShell in the download folder and run
`.\mux.exe --version`. To build from source with Rust 1.91 or later, run
`cargo install --git https://github.com/yuvichh/mux --tag v0.4.0 --locked cli`.

## What changed

- **Four words in place of a ticket.** `mux send ./photos` gives four words,
  and `mux get` with them on any other machine fetches the folder. Neither
  machine needs an address of the other, the words work for the first
  machine that uses them and for no other, and both commands end by
  themselves. The words are read however they are typed, and each by its
  first four letters.
- **Copy from and to a machine you can `ssh` to.** `mux cp server:/srv/site ./`
  and `mux cp ./site server:/srv/`, written as `scp` writes them. Nothing
  is installed on the other machine and nothing is set up: mux runs the
  `ssh` of your system. A copy that was cut off carries on, and a second
  run sends nothing. `mux sync` and `mux probe` read from the same places.
- **A secret in every ticket.** A machine that offers answers only who
  proves it knows the ticket's secret. `--to ID` lets in only the machines
  that are named, `--once` only the first that asks, and `--swarm` makes a
  ticket whose holders fetch from each other.
- **Small files, up to twenty times as fast.** A file still gets its name
  only once its bytes will last through a power cut. The flush that takes
  is now paid once for many files and not once for each.
- **A copy that was cut off fetches what is missing.** Run again, a copy of
  a folder leaves alone every file that is there with the size and the time
  of its source. It used to fetch all of them again unless every one was
  there.
- **`mux get` takes anything that can be fetched**: four words, a ticket, a
  web address or `host:path`, into the current folder unless another is
  named.

## Next to the tools it takes the place of

Two machines on one home network, the tools taking turns. The figures and
how they were taken are in
[the performance notes](https://github.com/yuvichh/mux/blob/v0.4.0/docs/performance.md).

| 3,000 files of 16 KiB | mux | Others |
| --- | ---: | --- |
| From one folder to another, macOS | 0.4 to 0.6 s | `cp -R` 0.6 s, `rsync` 0.6 s. mux 0.3 took 10 s. |
| From a machine, over SSH | 2.4 s | `rsync` 2.0 to 2.4 s, `rclone` 104 to 116 s, `scp` 104 to 134 s |
| To a machine, over SSH | 3.4 to 4.4 s | `rsync` 2.5 to 3.3 s, `scp` 105 s |
| With four words | 3.8 to 3.9 s | `sendme` 4.7 to 5.8 s, `croc` 27 to 40 s |

A large file goes as fast as the link carries it with each of them.

## Upgrading from 0.3

- **0.4 does not talk to 0.3.** Upgrade every machine that takes part, and
  make tickets again: a ticket of 0.3 has no secret, and is refused with a
  line that says so.
- **A machine that fetches no longer serves**, unless the ticket was made
  with `--swarm`. A fleet that fills from one machine adds `--swarm` where
  it offers.
- With `--json`, the `file` lines of small files can come several at a
  time. Each is still written when the file has its name.
- `mux send` writes the words alone on standard output only when that is
  not a terminal. A person is shown them on standard error.
- A copy to a machine reached by SSH is not flushed to that machine's disk,
  as with `scp` and `rsync`.
